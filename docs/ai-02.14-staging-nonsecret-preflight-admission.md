# AI-02.14 — staging nonsecret preflight admission

## Decision

AI-02.14 fixes the metadata boundary for the next possible staging preflight.
It permits only a future check of nonsecret credential presence, a required
application-owner identity preflight and deploy-preview transport context. It
does not inspect a credential value, a source row or an application-owner
identifier.

The preflight remains constrained by the staging aggregate result
`no_completed_bundle_available`. It is not a way to manufacture a completed
bundle, widen the one-shot source design, or treat the existing five-batch /
ten-snapshot scheduled evaluator as eligible.

## Authority boundary

The contract is server-only and I/O-free. A valid plan returns
`staging_nonsecret_preflight_scope_validated_not_authorized_not_executed`.
It does not open a staging connection, read an environment value, call a
provider or evaluator, deploy an adapter, write an outcome or apply the v2
migration.

The actual metadata-only preflight remains separately authorized and must
produce only minimized nonsecret evidence. Dataset, evaluation, promotion,
runtime, broker and production authority remain excluded.

## Value and next gate

This makes the next external read reviewable without normalizing secret access
or branch deployment as a prerequisite. It prevents a future implementation
from silently converting a presence check into a secret read or runtime action.

The next gate is one separately authorized staging-only execution of the
nonsecret credential-presence and branch-transport preflight. It must not read
credential values or source rows, invoke the provider/evaluator, deploy the
adapter or change production behavior.
