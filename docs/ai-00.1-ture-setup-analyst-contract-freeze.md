# AI-00.1 — Ture Setup Analyst contract freeze

## Bounded outcome

Freeze the first Agent Intelligence input/output boundary as a pure,
provider-free TypeScript contract. The `Ture Setup Analyst` can later assess an
already canonical candidate and its entry/stop/target plan, but it cannot
invent a replacement plan or change a canonical Ture decision.

## Delivered boundary

- The request accepts only canonical identifiers, capture time and an existing
  entry/stop/target snapshot.
- The only declared future tool identifiers are the six read-only context
  tools defined by the program plan. This action implements no tool and no
  agent runner.
- The assessment has a closed root shape, bounded string lists, explicit
  versions, a numerical confidence range and optional trace identity.
- Every accepted assessment is rebuilt with an immutable authority object that
  is permanently `shadow_only` and denies recommendation, ranking, risk,
  position and broker/order authority.
- Malformed, widened, accessor-backed or non-local output fails validation.

## Explicit non-goals

This action adds no OpenAI or Agents SDK invocation, API key, model selection,
environment variable, route, queue, database write, Netlify binding, provider
call, broker operation, recommendation/ranking mutation or UI integration.
It is a default-off contract for a future shadow runner only.

## Verification

`tests/e2e/ai-00.1-ture-setup-analyst-contract-freeze.spec.ts` proves the
default-deny request shape, valid immutable shadow assessment, rejection of
authority escalation and widened/accessor material, source-level absence of
runtime/provider bindings, and exact registration in the existing
provider-free CI plan.
