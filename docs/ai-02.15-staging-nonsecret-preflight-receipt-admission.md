# AI-02.15 — staging nonsecret preflight receipt admission

## Decision

AI-02.15 defines the only reportable shape of a future metadata-only staging
preflight. The receipt may say only whether the required server-managed
credential is present, whether the application-owner preflight is confirmed,
and whether deploy-preview transport is available. It returns no credential
value or name, application-owner identifier, deploy URL or identifier, source
row or result payload.

Both favorable and unfavorable facts are accepted as observations. A favorable
receipt is not approval to prepare an adapter, invoke the provider or
evaluator, persist an outcome or change any environment.

## Authority boundary

The contract is server-only and I/O-free. It does not run the preflight,
connect to staging, read an environment variable or call Netlify, Supabase, an
identity provider or a market-data provider. It emits
`nonsecret_preflight_receipt_validated_not_authorized_not_executed` only after
rejecting every raw credential, identifier, row and downstream binding.

Dataset, evaluation, active-evidence, runtime, broker and production authority
remain excluded. The aggregate `no_completed_bundle_available` result remains
unchanged, and this contract cannot make the scheduled five-batch/ten-snapshot
operation eligible.

## Value and next gate

This receipt boundary lets a later, separately authorized external preflight
be independently reviewed without allowing accidental secret or deployment
telemetry into the application or roadmap evidence. It also makes an
unfavorable result usable progress: it records only the missing prerequisite,
not a sensitive explanation.

The next gate is a separately authorized review of one minimized staging
receipt before any preparation of a one-shot branch adapter. It still cannot
invoke a provider/evaluator, deploy the adapter, write an outcome or affect
production behavior.
