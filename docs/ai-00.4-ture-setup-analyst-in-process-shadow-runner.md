# AI-00.4 — Ture Setup Analyst in-process shadow runner

## Bounded outcome

Define one deterministic, in-process-only runner boundary that accepts an
already accepted AI-00.1 shadow assessment and returns the existing AI-00.3
metadata-only shadow trace. “Emitted” means returned in memory to the direct
caller only; it does not mean logging, storage, delivery or export.

## Delivered boundary

- The runner accepts only a frozen, validated shadow assessment plus a closed
  metadata record already required by AI-00.3.
- It delegates trace construction to the existing trace contract, which binds
  trace/agent/model/prompt versions and applies the existing closed privacy and
  tool-ID policy.
- Equal accepted input produces equal scalar output, while every run result and
  trace is freshly immutable. The runner does not add a model inference,
  context-tool invocation or decision path.
- Its explicit authority is `in_process_shadow_only`, provider `unbound`, and
  denies model/tool invocation, I/O, trace persistence/export, canonical
  recommendation/ranking/risk/position/execution change and broker actions.

## Explicit non-goals

This action adds no Agents SDK/OpenAI call, model configuration, API key,
environment variable, provider request, context-tool adapter, database access,
trace/logging sink, route, queue, UI, deployment or broker operation. It also
does not retain an assessment, prompt or model output after the in-process
return.

## Verification

`tests/e2e/ai-00.4-ture-setup-analyst-in-process-shadow-runner.spec.ts` proves
that the runner consumes only an accepted frozen assessment, emits only the
existing metadata trace in a fresh frozen envelope, remains deterministic for
equal input and fails closed on mutable, widened or accessor-backed material.
It also proves exact one-time registration in the existing provider-free CI
plan.
