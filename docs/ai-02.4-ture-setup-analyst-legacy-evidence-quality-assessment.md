# AI-02.4 — Ture Setup Analyst legacy-evidence quality assessment

## Product decision

AI-02.4 is a server-only, provider-free and source-only assessment boundary
for a compact, already obtained profile of the private staging legacy-evidence
relation. It confirms the only safe conclusion that this relation can support:
the records are preserved historical context, not canonical evaluation evidence.

The boundary receives no rows, hashes, identifiers, ticker, JSON payload,
source record, secret or broker field. Its closed profile includes only a
bounded count, the equal count of distinct opaque hashes, the fixed legacy
disposition and four explicit absence facts for canonical evidence.

## Assessment result

An accepted frozen profile produces a fresh immutable result with:

- `noncanonical_preservation_confirmed` status;
- the two non-sensitive aggregate counts;
- a closed, sorted set of missing-evidence reason codes; and
- `not_admitted` for canonical evaluation.

The assessment cannot turn a legacy record into a canonical decision. In
particular it requires the absence of canonical decision identity, immutable
lineage, versioned reproducibility and complete outcome evidence. A profile
with a mismatched opaque-hash count, a changed fixed disposition, an asserted
canonical field, an empty or out-of-bound count, a mutable input, an accessor
or an extra field fails closed.

## Explicit exclusions

AI-02.4 reads no database or repository and does not access staging or
production. It performs no network or file I/O, secret lookup, writer call,
persistence, dataset formation, evaluation, model/provider call, route, UI,
runtime binding, deployment, ranking, policy promotion or broker action.

It is neither a durable receipt nor a trusted source profile. A future
canonical evaluation source still requires a separate product decision and
complete decision, lineage, version and outcome evidence.

## Evidence required for this slice

- a valid frozen noncanonical preservation profile yields a fresh frozen,
  default-deny assessment;
- mismatched counts, widened or asserted-canonical profiles fail closed; and
- mutable, accessor-backed and faulting proxy containers fail without
  evaluating an accessor or proxy trap.
