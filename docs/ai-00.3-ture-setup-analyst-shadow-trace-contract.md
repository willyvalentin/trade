# AI-00.3 — Ture Setup Analyst shadow trace contract

## Bounded outcome

Define a pure, metadata-only trace record for one accepted shadow assessment.
It makes the Agent Intelligence roadmap's latency, token and estimated-cost
metrics measurable without retaining a prompt, model output, secret or
unnecessary personal data.

## Delivered boundary

- A trace is bound to a closed AI-00.1 shadow assessment and must reuse that
  assessment's trace, agent, model and prompt identities exactly.
- The trace records only candidate/recommendation linkage, versions, declared
  AI-00.2 tool identifiers, latency, input/output token counts and estimated
  USD cost.
- Privacy is a closed, immutable metadata-only declaration: no secrets, no
  unnecessary personal data, no raw prompt and no raw model output.
- Metrics are bounded finite values. Tool identifiers must be unique and must
  come from the existing six-tool AI-00.2 policy.
- The output is fresh and immutable, with no I/O, persistence or export
  authority and the same permanent denials of canonical recommendation,
  ranking, risk, position, execution and broker/order authority.

## Explicit non-goals

This action adds no Agents SDK/OpenAI call, API key, environment variable,
provider/database access, logging sink, trace export, route, queue, UI,
scanner/ranking mutation, deployment or broker operation. It does not claim
that an external tracing system is configured. A future trace sink, shadow
runner or evaluation harness needs its own bounded review.

## Verification

`tests/e2e/ai-00.3-ture-setup-analyst-shadow-trace-contract.spec.ts` proves
closed metadata, version and trace binding, cost/latency/token bounds,
privacy/default-deny authority, fail-closed rejection of sensitive/widened or
accessor-backed material, and exact registration in the existing provider-free
CI plan.
