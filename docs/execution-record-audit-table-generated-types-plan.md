## 4. Type Generation Command Plan

The commands below are future/manual commands. They were not executed in Action 737.

Capture target environment and project/ref identity:

```bash
supabase status
supabase projects list
```

Generate TypeScript types after the audit migration and remote table are proven:

```bash
supabase gen types typescript --linked --schema public > lib/database.types.ts
```

If the team uses a project ref instead of linked context, record the approved project ref first and use:

```bash
supabase gen types typescript --project-id <project-ref> --schema public > lib/database.types.ts
```

Capture command output separately from the generated file when possible:

```bash
supabase gen types typescript --linked --schema public > lib/database.types.ts 2> docs/artifacts/audit-table-generated-types-command-output.txt
```

Capture generated file diff:

```bash

```

Future evidence must include target project/ref/environment source, target schema, output path, command output path, generated file diff, reviewer, date, and pass/fail result.

- JSONB fields should map consistently to the repository's generated JSON type.
- Timestamp fields should map consistently with existing generated Supabase timestamp strings.

## 7. Type Drift/Blocker Rules

Block type adoption if any of the following occur:

- Missing `execution_record_audit_events` table.
- Missing `Row`, `Insert`, or `Update`.
- Wrong nullability.
- Missing FK relationship when relationship metadata is expected.
- Missing `idempotency_key`.
- Missing `duplicate_prevention_key`.
- JSONB fields typed unexpectedly.
- Timestamp fields typed unexpectedly.
- Generated types came from the wrong environment.
- Generated file was not committed or reviewed.
- TypeScript compile fails after generation.
- Generated types do not match verified remote schema.

Block writer design/implementation until the generated audit table types are present, reviewed, and compile cleanly.
