# AI-00.5 — Ture Setup Analyst fixture evaluation harness

## Bounded outcome

Define a deterministic, fixture-only evaluation boundary. It compares one
already accepted Setup Analyst shadow assessment and its admitted in-process
shadow trace against a frozen canonical decision plus a realized-outcome sample.
The result is a small in-memory comparison record, not a scorecard, trend,
promotion decision or persisted evaluation dataset.

## Delivered boundary

- A fixture has a closed identity, freeze timestamp, canonical trade or
  no-trade decision, and bounded realized-R/MFE/MAE outcome values.
- Evaluation accepts only a frozen fixture, a frozen accepted assessment and an
  exact admitted AI-00.4 runner result whose trace is cross-bound to that
  assessment's identity, versions and trace ID.
- The result exposes only canonical/agent decision comparison, realized outcome
  direction and scalar trace cost/latency metrics. It retains no raw evidence,
  prompt, model output, full assessment or full trace.
- Every result is fresh and immutable. Its authority is fixture-only and denies
  model/tool invocation, I/O, persistence, promotion, canonical state change,
  execution and broker actions.

## Explicit non-goals

This action adds no model, provider, context-tool, database or outcome source;
no evaluation sink, route, queue, UI, batch runner, deployment or broker
operation; and no model or policy promotion. Frozen fixture material is a
local contract input only, not a claim that a realized-outcome data pipeline is
live.

## Verification

The AI-00.5 fixture-evaluation harness test proves deterministic fixture
comparison, cross-binding, no retained rich assessment material, fresh
immutable output, fail-closed rejection and exact one-time registration in the
existing provider-free CI plan.
