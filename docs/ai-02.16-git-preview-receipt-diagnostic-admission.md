# AI-02.16 — Git deploy-preview receipt diagnostic admission

## Decision

AI-02.16 defines the only local plan shape for diagnosing why the one-time
Git deploy-preview preflight returned no admissible minimized receipt. It
permits a future, separately authorized diagnostic to observe only a response
status class and whether a response has the fixed receipt shape. The plan is
limited to one token-protected `GET` request in a staging deploy-preview
context.

The plan does not contain a credential value or name, application-owner
identifier, deploy identifier or URL, response body or headers, source row or
result payload. It treats all of those as required redactions.

## Authority boundary

This implementation is server-only and I/O-free. It does not run a request,
connect to staging, read an environment variable, access a credential, call
Netlify, Supabase, an identity provider or a market-data provider. A valid
result is only
`git_preview_receipt_diagnostic_plan_validated_not_authorized_not_executed`.

The implementation cannot deploy an adapter, persist an outcome, apply a
migration, write active evidence, form a dataset, evaluate, bind runtime,
invoke a provider or evaluator, or affect a broker or production.

## Value and next gate

The contract turns the missing-receipt problem into a small, auditable next
decision instead of permitting a retry that could reveal secrets or transport
metadata. A future diagnostic still requires separate authorization and must
return only the two permitted observations; it creates no preflight, source
creation or runtime authority.
