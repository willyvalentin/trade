## Previous Prerequisite Weakness

Before remediation, the authority-package contract verified prerequisite fingerprints and a selected subset of fields. A caller could construct accepted-looking prerequisite evidence with a recomputed fingerprint while leaving unchecked authority or live/runtime fields contradictory.

## Corrected Prerequisite Posture

The remediated contract rejects recomputed forgeries across:

- executable-resolution evidence;
- immediate pre-spawn revalidation evidence;
- read-only Git compatibility results;
- approved aggregate worktree linkage.

The validator now enforces exact fixture/non-live posture, accepted status and reason posture, no blocking/ambiguity arrays, exact `/usr/bin/git`, exact macOS/session/policy/linkage fields, no process/spawn/shell/observer/credential/network/API/UI/trading/Avanza/persistence/deployment/authorization authority, no retry/fallback escalation, no runtime activation, no TOCTOU elimination claim, and deterministic prerequisite fingerprints.

## Previous Schema Weakness

The prior Action 607 schema relied on helpers that used enumerable own keys. That could miss non-enumerable string properties and did not close nested arrays against attached properties, symbols, sparse entries, accessors, exotic prototypes, or shadowed array methods.

## Exact Object And Array Closure

The remediated contract uses private exact schema helpers.

Objects must be non-null plain objects with prototype exactly `Object.prototype`, exact own string keys via `Reflect.ownKeys`, no symbols, all approved properties as enumerable data properties, no accessors, no non-enumerable extras, and no inherited enumerable fields.

Arrays must have prototype exactly `Array.prototype`, exact length, own keys exactly canonical indexes plus `length`, no symbols, no accessors, no holes, no extra string keys, no noncanonical numeric keys, no subclass/exotic prototype, no shadowed methods, and exact expected element values where an exact array is expected.
