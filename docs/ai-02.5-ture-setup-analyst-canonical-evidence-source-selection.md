# AI-02.5 — canonical evidence-source selection

AI-02.5 makes the next Agent Intelligence decision explicit without creating
any evidence row. It selects only the *shape* of a future source that can be
reviewed later: one staging-only, append-only `historical_synthetic` decision
in `public.canonical_evaluation_decisions`.

The selection is deliberately not a database adapter, a write permission, or
a claim that such a row exists. Staging currently has no canonical-evaluation
rows, and the private legacy-evidence relation remains non-canonical.
AI-02.5 does not make legacy history canonical.

## What the selected future source must contain

The bounded proposal requires all of the following before a future operation
can even seek separate admission:

- a canonical decision identity;
- immutable decision lineage;
- versioned reproducibility;
- a complete primary outcome; and
- a canonical persistence envelope.

The initial permitted sample class is `historical_synthetic`. It is useful for
testing the governed source path without relabelling preserved legacy history
or claiming real-world quality evidence.

## Boundaries

AI-02.5 is server-only, pure and provider-free. It accepts a frozen static
proposal and returns a detached frozen selection. It performs no I/O, does not
read either environment, and sees no row, identifier, outcome scalar, ticker,
JSON payload, secret or broker value.

Its result is always `not_admitted` for canonical evidence. A separately
authorized staging-only append-only receipt proof is still required before any
record can exist. That later proof must remain distinct from writer/runtime
binding, offline dataset formation, evaluation, model/provider use, deployment,
broker activity and production authority.
