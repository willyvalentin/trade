# AI-02.17 — source-route external-request budget audit

## Scope and outcome

This is a read-only, provider-free review of the existing Draft adapter in
PR #397 at commit
`30a6d733407544c15ce9ec6f3b3d2dc58032cdab`. It was performed on
2026-09-07 before any admitted market window. It neither invokes the Draft
adapter nor reads a staging environment, secret, source row, provider or
calendar response.

The review finds that the Draft adapter is **not yet ready to execute** under
the one-shot AI-02.17 decision. The adapter correctly fixes the scan's own
candidate and result bounds, but the canonical scan route it invokes can make
an additional external calendar-provider request before it reaches the
one-candle scan budget.

## Evidence

The source adapter invokes `/api/automation/run-scan` after it reserves its
single source marker. The route then calls `getUsMarketStatus()` before it
starts the bounded scan. In `lib/market-calendar.ts`, a stale or absent
`market_calendar_cache` row causes `getUsMarketStatus()` to call
`getPolygonMarketStatus()` and then upsert the result into the cache.

That possible Polygon request is outside AI-02.17's fixed allowance: one
forced-fresh source candle request, followed only after maturity by one reused
evaluator candle request. The decision deliberately permits at most two
provider requests in total and requires its source receipt to account for
exactly one source candle request. A cache miss could therefore make the
operation exceed its provider limit despite the adapter's local budget flags.

## Decision and containment

Treat this as a **blocking readiness finding**, not as a failed evidence
operation. The marker has not been consumed and no remote action occurred.
Do not invoke PR #397's source function in the next market window until a
separately reviewed, provider-free way to prevent the nested calendar fetch
and cache write has been implemented and verified.

The smallest acceptable resolution must preserve all existing boundaries:

- use the repository-owned verified session result already checked by the
  temporary adapter, or a separately bounded equivalent, without a second
  provider call;
- stop before source-marker reservation if that result is unavailable or
  incompatible;
- preserve the one-ticker, one-recommendation, one-fresh-source-candle bound;
- add a focused test proving a cold calendar-cache path cannot call Polygon or
  write `market_calendar_cache` during AI-02.17;
- keep the adapter Draft-only and remove it, its branch-only token and its
  fixture after its sole eventual proof.

This audit does not authorize a change to the adapter, a function deployment,
a staging connection, a provider call, a source marker, persistence, a cohort,
runtime binding, broker activity or production access. It does not change or
reopen PR #397.

## Local remediation verification

On 2026-09-07, the isolated local candidate
`codex/ai-02-17-source-budget-revalidated` resolved the cold-cache concern
without invoking an external service. Its bounded resolver selects the
repository-owned verified US-equity session only when both AI-02.17 request
bindings are exact; otherwise the ordinary calendar path remains unchanged.
The focused regression suite proves that an admitted AI-02.17 request never
calls the default cold-cache calendar lookup, while holiday and early-close
results remain fail-closed or bounded from the same static calendar.

The candidate also rejects a forged source receipt reporting two successful
candle requests. Together with the existing outcome receipt test, that gives
the temporary adapters explicit negative coverage for an over-budget source or
outcome response, with fixed redaction in the returned failure receipt. The
21 focused AI-02.17/AI-02.18 Playwright tests, targeted ESLint and
`tsc --noEmit` passed locally at candidate commit
`9ff5cd44127c577e64d5bc39d652092874efbbb1`.

A follow-up request-boundary review added explicit hostile-input coverage at
candidate commit `fbe70b82`: a truthy string, numeric value, or lookalike
source name cannot select the local AI-02.17 calendar path. Commit
`edef99b9` then made the automation route import the same source constant as
the resolver, preventing future literal drift while retaining the exact
boolean comparison at the untyped request boundary. The six focused market
status tests, targeted ESLint, and `tsc --noEmit --incremental false` passed
locally. This is local readiness evidence only; it neither invokes an adapter
nor changes the operation's staging-only, one-shot authority.

Two further local regression commits, `019484c0` and `56cc5a2a`, bind the
same suite to every secondary market-data and regime path, then to the forced
one-ticker, one-recommendation, model-free scan bounds. The focused suite now
has seven passing tests. They prove the one-shot branch disables dynamic-mover
discovery, fresh indicator refreshes, market-regime lookup and its ancillary
snapshot while retaining exactly one deliberate fresh source-candle path.

At candidate commit `b1bab7b1`, the complete local AI-02 suite — from the
canonical projection contracts through both temporary one-shot adapters —

guards do not weaken the earlier source-only, inactive-evidence, or outcome

After that containment change, the candidate's local `npm run build` and

`ai02-staging-one-shot-outcome.ts`. This is packaging evidence only: no

This is local readiness evidence only. The candidate has not been pushed or
