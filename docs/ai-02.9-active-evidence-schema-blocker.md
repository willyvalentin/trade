# AI-02.9 — Active evidence schema compatibility blocker

## Status

Blocked before write. This is an implementation finding, not an admission of a
new cohort, evaluator, runtime, provider/model, deployment, broker or
production capability.

## Evidence

On 2026-09-06, the separately authorized, staging-only AI-02.8 execution
preflight inspected only the definition of
`public.canonical_evaluation_decisions`' envelope-consistency constraint in
`ture-staging`. It confirmed that the deployed constraint requires
`(persistence_envelope ->> 'inactive_readiness_only')::boolean = true`.

The checked-in v1 persistence and storage builders deliberately enforce the
same invariant. That is consistent with the one existing
`historical_synthetic` receipt, but contradicts AI-02.8's required
`inactive_readiness_only=false` for a genuinely complete decision-and-outcome
bundle. A complete active row could therefore not be inserted truthfully, and
an inactive row could not be relabelled as active evidence.

The same preflight also performed one outcome-minimized aggregate against
`public.recommendation_outcomes`. It returned zero total, non-pending and
recognized-horizon rows. Staging therefore has no existing server-owned
completed recommendation-and-outcome bundle to supply, independently of the
v1 compatibility conflict.

No row payload, owner identifier, JSON payload or secret was read. No DML,
schema change, application writer, runtime, deployment, provider/model,
broker or production action was performed.

## Decision

Do not weaken or reinterpret the existing v1 inactive-readiness contract. It
is part of the provenance of the historical synthetic receipt and must remain
immutable.

The next implementation prerequisite is an additive, separately reviewed
active-evidence contract, matching schema migration and a bounded
server-owned source path that:

1. preserves existing v1 inactive rows and their append-only trigger;
2. gives genuinely complete evidence an explicit new contract/version rather
   than changing the meaning of v1;
3. rejects an active row unless it carries canonical identity, recomputable
   semantic digest, complete primary outcome and diagnostic horizons;
4. remains staging-only, default-off and independent of any evaluator,
   promotion, runtime, provider/model, deployment, broker or production path;
   and
5. creates a genuine completed bundle without using a fixture, the existing
   historical receipt or the legacy-preservation relation; and
6. is locally verified before a separate staging migration authorization,
   identity/digest preflight, one bounded append-only insert, containment and
   independent minimized readback are considered.

The future source must still be a real server-owned completed recommendation
and outcome bundle. A fixture, the historical synthetic receipt, or the
private legacy-preservation relation cannot satisfy this prerequisite.
