# AI-02.1 — Ture Setup Analyst canonical outcome projection

## Product decision

AI-02.1 is the selected next provider-free product slice after the completed
AI-01.1–AI-01.4 local-fixture sequence. It supplies the narrow bridge that a
future offline evaluation needs: a server-only projection can accept one
already loaded, frozen and eligible canonical-evaluation read-model snapshot,
then retain only the minimum scalar outcome, confidence and version evidence.

It is deliberately not a dataset, repository query, batch runner or evaluation
result. The projection remains `not_admitted` for offline evaluation and for
every form of promotion. Its purpose is to prevent a future Agent Intelligence
cohort from silently mixing incomplete, non-reproducible or noncanonical
outcome material with the canonical quality model.

## Authorized source-only boundary

The adapter accepts no client input, reads no repository and owns no provider,
environment or persistence access. Its caller must supply a frozen canonical
quality read-model snapshot whose primary 60-minute outcome is complete,
reproducible, parity-verified, cohort-quality eligible and semantically a
probability confidence. The sample-type and cohort pairing must be canonical.

The output is a fresh frozen server-only DTO. It retains no ticker, sector,
raw horizon data, diagnostic reason codes, repository handle or callback. A
malformed, mutable, incomplete, mismatched or accessor-backed input fails
closed.

## Explicit exclusions

AI-02.1 performs no Supabase/read-model query, model or context-tool call,
provider access, file/network I/O, secret/environment lookup, persistence,
route, queue, UI or runtime binding. It changes no recommendation, ranking,
risk, position, execution eligibility or broker state. It does not claim that
real outcome data was read, that an offline cohort is statistically adequate,
or that a model or policy can be promoted.

An actual read-only cohort query, frozen time-based holdout, measured result
and human promotion review remain separate decisions with their own authority
and evidence requirements.

## Evidence required for this slice

- focused tests for a valid eligible canonical snapshot and a fresh, redacted,
  immutable output;
- fail-closed tests for mutable, incomplete, mismatched and accessor-backed
  input; and
- normal Ready Full CI before merge, followed by exact-main verification.
