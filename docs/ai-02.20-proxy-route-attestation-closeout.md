# AI-02.20 — proxy-route attestation closeout

**Status:** closed on 2026-09-08 — the repository-owned cause of AI-02.18's
HTTP `401` was identified, but the single replacement route proof returned only
the function's uniform HTTP `404`, not its fixed receipt.

## Bounded objective

AI-02.20 was a diagnostic-only successor to AI-02.18. It was permitted to
test whether a temporary no-provider function can pass the application proxy
when placed under the already allowlisted `/api/automation/` prefix. It did not
create authority for a staging connection, source row, provider, database,
evaluator, writer, runtime, deployment, broker or production operation.

- Repository inspection established that `proxy.ts` requires an application
  session before dispatch for API paths outside its explicit public allowlist.
  AI-02.18's temporary route was outside that allowlist, which accounts for its
  `401` without relying on an unidentified Netlify Edge or platform layer.
- Temporary PR #412 was built from
  `1d880669424322856e4b5c33853e0857fdf687d6`. Ready Full CI run
  `34274316594` passed the unchanged six-shard suite, protected aggregate and
  merge-candidate provenance check for that commit.
- Its matching Netlify deploy-preview
  `6aa06d74b56d090008e89d26` was ready for the same branch and commit, and
  carried the temporary POST-only function at
  `/api/automation/ai02-proxy-route-attestation`.
- The function was locally verified to return one fixed redacted receipt only
  for the matching branch-deploy context and one matching token. Wrong method,
  token, context, site or absent secret returns the same HTTP `404` response.
- Exactly one POST was sent to that matching deploy-preview. It returned HTTP
  `404`, so no success receipt, credential, source, provider, database,
  evaluator or runtime fact was established.

## Containment and consequence

The one-request budget is consumed and no request may be retried. The temporary
branch-scoped proof-secret cleanup command was invoked after the request. PR
#412 was closed without merge; its remote and local branches and isolated
worktree were removed. The temporary function and its fixture never reached
`main`.

This closes the previous unknown-upstream attribution: the former HTTP `401`
was caused by the repository proxy's session gate. It does **not** prove that
the public-prefix route had the required branch secret or any other
configuration at invocation time, and it does not establish a working transport
or authorize a replacement operation. The missing local server-owned owner
principal remains a separate pre-dispatch blocker for the existing scan route.
