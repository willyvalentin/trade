# AI-02.17 — staging actual-evidence operation decision

## Decision

On 2026-09-07, the product owner separately authorized one staging-only
AI-02 operation that may use real market-data-provider access to create the
otherwise unavailable server-owned completed-outcome source. This is a new
actual-evidence operation, not a third repetition of AI-02.16's failed
metadata-only transport preflight.

The operation may create at most one official server-owned recommendation
snapshot through the canonical scheduled scan path. Only after that source is
at least 60 minutes old may it perform one canonical outcome evaluation for
the same source. The evaluator is limited to one batch, one snapshot, and one
reused market-data candle request for the 15/30/60-minute outcome bundle.
The distinct source scan is limited to exactly one forced fresh market-data
request. Therefore the operation permits at most two provider requests in
total: one source dataset request and, only after source maturity, one reused
outcome-evaluation candle request.

No execution has occurred under this decision. The first eligible date,
2026-09-07, is a verified US-market holiday and is therefore rejected before
the operation can make a staging, identity, provider, or durable-marker call.

## Preconditions and containment

The actual operation is admissible only when every condition below is true:

- It uses an isolated Draft deploy-preview adapter pinned to staging and to a
  one-time proof token held only in branch-scoped function configuration.
- A verified repository-owned US-equity calendar reports a regular or
  early-close session, the source is at least 15 minutes after session open,
  and it is before both session close and the configured 15:00 New York
  cutoff. A holiday, weekend, stale or unavailable calendar fails closed
  before the one-shot marker.
- The source route is the existing authenticated official scheduled scan
  route, with a hard limit of one ticker and one recommendation. It skips the
  model call but retains exactly one forced fresh official market-data request
  required to create genuine source evidence. The one-shot provider budget
  disables dynamic-mover discovery and the market-regime lookup, and disallows
  fresh reference-refresh requests. Its redacted receipt rejects any scan
  trace that does not account for exactly one source candle request.
- The temporary adapter reserves exactly one durable source marker before
  dispatch. It returns only a fixed-redaction receipt: no credential values,
  identifiers, URLs, row data, ticker, or provider payload.
- The outcome adapter may reserve its own marker only after a successful,
  mature source marker. It returns the same fixed-redaction receipt shape.

If a prerequisite is unavailable before the source marker, the operation
stops with no marker consumption. If the source marker is consumed but the
canonical route yields no usable source or the outcome proof fails, the result
is recorded as a bounded fail-closed outcome; it is not retried under this
decision.

After either a successful proof or a definitive fail-closed result, the
branch-scoped proof configuration and protected local token file must be
removed, the Draft adapter pull request must be closed, and its exact
worktree/branch removed. The temporary adapter code must never merge.

## Authority boundary

This decision authorizes only the bounded staging source/evaluation operation
above. It does not authorize a shared migration, an active-evidence write,
cohort formation, offline evaluation, policy promotion, runtime binding,
deployment, production access, broker action, or a general provider permit.

The earlier AI-02.16 direction against a third temporary *preflight* request
remains historical and unchanged. It does not govern this separately
authorized actual-evidence operation. No broader precedent is created: a
different provider, production system, or subsequent source attempt needs its
own explicit decision.

AI-02.13's one-request ceiling applies to the reusable evaluator candle for
the 15/30/60-minute bundle. This decision makes the separately necessary
source-scan request explicit and caps the two stages independently; it does
not expand either stage or authorize a general provider budget.

## Evidence and next gate

Success requires both independently redacted receipts and an aggregate-only
staging readback proving the single bounded source and complete outcome bundle
without returning source material. The source/outcome evidence remains staging
evidence only; it does not itself admit v2 persistence or any evaluator,
promotion, runtime, deployment, broker, or production successor.

The next gate after a successful proof is a separate decision that evaluates
whether the resulting source is eligible for the existing canonical-evidence
contracts. A failed or unavailable proof closes this one-shot operation and
returns prioritization to the master roadmap without retrying it.
