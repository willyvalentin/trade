# AI-00.2 — Ture Setup Analyst read-only context-tool boundary

## Bounded outcome

Define the only provider-free boundary through which a future `Ture Setup
Analyst` may request context. This is a contract for six named tools, not an
implementation of any tool or a permission to retrieve data.

## Delivered boundary

- The boundary accepts only an already canonical, `shadow_only` AI-00.1
  request and one of its six declared tool identifiers.
- Each generated request is immutable, bound to the original canonical
  snapshot and capture time, and has a separate scope-specific minimized input
  set. It never copies the entry/stop/target plan, an assessment, model
  metadata or arbitrary caller fields into a tool request.
- A future response must declare provenance and freshness, must not contain a
  source timestamp after the canonical capture time, and must make unavailable
  data explicit.
- The boundary is deliberately `unbound`: it performs no I/O and permits no
  context write, canonical recommendation/ranking/risk/position change,
  execution eligibility change, order action or broker instruction.

## Explicit non-goals

This action adds no model or Agents SDK call, API key, environment variable,
provider call, news call, database read/write, route, queue, scanner/ranking
mutation, persistence, deployment, Netlify binding, UI integration or broker
operation. A future adapter, response validator, trace record or runner needs
its own bounded review.

## Verification

`tests/e2e/ai-00.2-ture-setup-analyst-read-only-context-boundary.spec.ts`
proves the six exact tool policies, canonical source binding, per-tool data
minimization, immutable default-deny authority, and fail-closed rejection of
widened, accessor-backed or authority-escalating source material. It also
proves that this source has no provider, database, runtime or environment
binding and is registered exactly once in the existing provider-free CI plan.
