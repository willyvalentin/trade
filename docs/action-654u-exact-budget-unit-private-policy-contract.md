# Action 654U — Exact Budget-Unit and Private Policy Contract

## Scope

Action 654U is an additive, default-off, synthetic-only successor to the frozen
Action 654S/654T state. It closes `654T-M1` and `654T-M2` without changing any
predecessor byte or published PR #78 commit.

The sole production runtime operation is
`runAction654uExactBudgetUnitPrivatePolicy`. Types are erased at runtime. No
policy, policy factory, evaluator, boundary matrix, review projection,
privileged counter, or test helper is exported from the production module.

## Private production policy

The module-owned policy is frozen and contains exactly:

```text
maximum_code_units:128
maximum_observation_bytes:384
maximum_total_bytes:1984
```

It is not caller-supplied, cloneable, selectable, or mutable. An unexpected
third argument is rejected without inspection and with all work counters zero.
Test-only policies and integer proof helpers exist only inside the focused test
scope and are not imported by production.

## Exact unit proof versus runtime reachability

The contract keeps two explicitly different projections:

1. `exact_unit_proof` evaluates the integer budget relation at exactly
   `maximum − 1`, `maximum`, and `maximum + 1` for each configured unit.
2. `reachable_runtime_cost_proof` records costs generated by adjacent UTF-16
   code-unit counts in the actual encoding model.

The exact integer matrices are:

```text
code units:        127 / 128 / 129 around 128
observation bytes: 383 / 384 / 385 around 384
total bytes:       1983 / 1984 / 1985 around 1984
```

The runtime encoding has coarser granularity. For code-unit counts
`127 / 128 / 129`, it yields:

```text
observation bytes: 382 / 384 / 386
total bytes:       1976 / 1984 / 1992
```

These reachable costs are never relabelled as `maximum ± 1`. At 129 code
units, validation stops at the first code-unit budget, preserving fail-fast
zero-work semantics.

## Validation order and rejection semantics

The operation captures a primitive string once, reads its primitive length
once, then validates code units, framed observation bytes, and conservative
total bytes in that order using safe-integer multiplication and addition.
Only after all budgets pass may UTF-16 iteration, framing, hashing, JSON
parsing, canonical serialization, capsule work, readiness work, V5 work, or
confirmation consumption occur.

A budget rejection is bounded plain data. It reports policy version, reason,
bounded observed length, unit, and relevant maximum. It has no failure identity
or terminal digest and explicitly sets
`cryptographic_input_binding_claimed:false`.

## Preserved properties

- Exact big-endian UTF-16 code-unit observation without normalization or UTF-8
  replacement identity.
- Collision separation for lone surrogates, surrogate pairs, and canonically
  equivalent but code-unit-distinct strings.
- Hook-free primitive boundary and engine-owned canonical gate snapshot.
- Private Action 654H readiness provenance and atomic establishment.
- Invalid/default-off/kill-switch consumption zero and valid consumption once.
- Determinism across UTC, Stockholm, New York, fresh processes, and reversed
  fixture key order.
