# Action 666GL — Advisory accessibility-presentation selection

## Bounded objective

Select one smallest safe, source-only successor to the completed Action 666GK
static containment review. The selection may define a future accessibility
presentation boundary for the seven fixed Action 666GJ semantic keys, but it
must not implement a caller, read data, invoke an evaluator or bind a route,
component or ARIA attribute.

## Candidate evaluation

| Candidate | Decision | Reason |
| --- | --- | --- |
| Bind the keys to an `aria-live` region, component or route | Rejected | UI and route admission remain separately blocked; no DOM contract is authorized. |
| Read the evaluator, stored decision or caller state to produce wording | Rejected | The closed presentation vocabulary must not gain evaluation or data authority. |
| Add localized sentences, advice, prices, quantities or recommendations | Rejected | Copy and trading interpretation are wider product decisions, not static accessibility metadata. |
| Change CI, required checks, branch protection or Netlify | Rejected | Ready/exact-main Full CI, its six shards and deploy controls remain unchanged. |
| Select finite accessibility-announcement metadata keys | Selected | It retains the closed vocabulary and offers a deterministic, later-accessible presentation seam without runtime wiring. |

## Required containment

`ACTION_666GM` may add one standalone source-only projection that accepts only
the seven fixed Action 666GJ presentation-key literals. It may return only a
frozen accessibility-announcement key and an explicit rejected result. It must
not return prose, an ARIA attribute, a recommendation, price, quantity,
position, timestamp, identity, credential, provider, broker or execution
signal. It may not import the evaluator, read environment/network state, mutate
state, expose a route, render UI or assert execution authority.

This selection reopens no runtime capability. It authorizes only the explicitly
bounded source-only successor above; any caller, rendered accessibility UI or
wider capability requires a separate redesign-or-stop decision.
